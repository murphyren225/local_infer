# 企业内网 AI 集群:产品流程

> 目标体验:**买好硬件 → 每台一条命令 → 全公司一个内网 AI 入口**。
> 设备间不互相插线,全部通过企业现有局域网通信。

## 1. 用户输入

**安装期(一次性)**:

| 输入 | 必须? | 说明 |
|---|---|---|
| 每台设备跑一条安装命令 | 必须 | 见 §2 |
| 加入口令(第一台生成,其他台粘贴) | 必须 | 设备认 Hub,防蹭网 |
| 云端 API key 一行 | 建议 | 解锁云端兜底;不填也能跑,降级用幸存车道顶班 |
| 企业策略(云端预算上限、某类数据永不出网) | 可选 | Hub 网页上点选 |

**使用期(日常)**:网页控制台(打字+拖文件)、终端 `pi`(内网版编码 agent,
真实执行)、OpenAI/Anthropic 兼容 API(现有软件改个地址直接接入)。

## 2. 安装流程(CLI)

第一台设备(自动成为 Hub):

```
$ curl -sSL https://<发布地址>/install.sh | sh
$ homed init
  ✓ 探测硬件: RTX 4090D, 24GB 显存
  ✓ 选定档位: qwen3-24gb (强档 32B-AWQ + 弱档 1.7B-FP8)
  ✓ 下载模型(~22GB)... 启动车道... 启动网关...
  Hub 就绪: 控制台 :6006 / API :4000/v1 / 加入口令 JOIN-XXXX
```

之后每台设备(一行加入,零配置):

```
$ curl -sSL https://<发布地址>/install.sh | sh
$ homed join <Hub内网地址> --token JOIN-XXXX
  ✓ 探测硬件 → 自动选角色(见 §4) → 注册进 Hub
```

设备关机自动摘除路由,开机自动归队(看门狗机制,已实现)。
出厂预装节点镜像后,`join` 这步也能省掉:插电插网,Hub 网页点批准。

状态:单机版全流程(探测→选档→起栈→自愈)已于 2026-09 在 RTX 4090D 真机验证
(homed/run_cluster.sh);`init/join` CLI 封装与多机注册为二期,join 机制 1-2 天量级。

## 3. 硬件清单(按预算叠加)

| 档 | 设备 | 角色 | 状态 |
|---|---|---|---|
| 入门档 | 一台 24GB 独显机(4090/4090D/3090,约 ¥13k-20k 或按时租) | 单机即完整系统:强+弱共存 | ✅ 实测 |
| 标准档 | + 一台常开低功耗机(Mac/小主机) | Hub+弱档 24h 在线;独显机变按需开机(开关机=成本开关) | 📋 二期 |
| 旗舰档 | + 一台 128GB 大内存主机(DGX Spark / 懒猫 AI Pod / Perplexity 成品机) | 长文档车道:300B MoE,26万~100万 token 上下文 | 📋 调研完成 |
| 顺手 | 任何旧电脑 | 装 pi 当终端 | 📋 |

**联网要求**:所有设备在同一局域网(办公网本来就是),普通千兆网线/交换机足够。
我们每台设备跑完整模型、按车道分工,设备间只传 KB 级 API 流量——不需要
RoCE/InfiniBand。「切一个模型摊多台」的玩法(spark-bench 200G 组网、
distributed-llama 以太网张量并行)仅在单台装不下时封装成「算力舱」整体
当一个节点接入,舱内复杂度出厂封装,不暴露给客户。

## 4. 模型选择(用户不选,按硬件自动配)

| 探测到 | 弱档(走量~八成流量) | 强档(破局) | 状态 |
|---|---|---|---|
| 24GB 独显 | Qwen3-1.7B-FP8 | Qwen3-32B-AWQ(未来 Qwen3.8-27B) | ✅ |
| 12-16GB 独显 | Qwen3-1.7B-FP8 | Qwen3-8B/14B-AWQ | ⚠️ 外推 |
| 32GB+ 独显 | Qwen3-4B-AWQ | Qwen3-32B-AWQ | ⚠️ 外推 |
| Mac | Qwen3 系 4bit MLX | —(强档活交给其他设备) | 📋 |
| 128GB 主机 | 中档稠密 | GLM-5.3-Flash / DeepSeek-V4-Flash | 📋 |
| 云端(有 key) | — | Claude/GPT/Qwen 大杯(兜底) | ✅ |

换模型=管理员在 Hub 改档位名(homed/inference/presets/),不碰任何节点。
judge 与弱档同宿主。参考:Switchyard 官方出厂预置也是双档
(强:Opus/GPT-5.5;弱:Kimi/Gemini Flash/Nemotron——NVIDIA 自家模型放走量位)。

## 5. 任务指令

分配逻辑一句话:**任务先让弱档干,judge 盯干活轨迹,确认卡在弱档能力之外才升
强档,升级单程不回头;显式指定 small/large/cloud 永远直通;本地全灭走云端**。
(judge 的官方判据与 8 步流程见 docs/home-cluster.md)

| 类型 | 谁干 | 例子(可照抄) |
|---|---|---|
| 秒回类 | 弱档 | 「把这段翻译成英文」「这封邮件改礼貌点」「这条评论是好评还是差评」 |
| 专家类 | 强档 | 「分析这份合同的违约条款风险」「这段代码为什么死锁:```…```」 |
| 文档类 | 按长度分档 | 传报表→「总结要点标出异常」;传 CSV→「哪些行可疑」;传代码→「讲讲这模块」 |
| Agent 类 | 弱档起步自动升级 | 「写个脚本统计目录文件数,运行给我看」「把仓库里所有 TODO 列成清单」 |

能力路线:✅ 单机档四类任务全部可用(真机验证,含故障切换演练);
📋 二期:init/join 多机、长文档车道、看图(Qwen3.8/DS-V4-Vision)、
Google Docs 等外部系统(Pi 扩展)。
