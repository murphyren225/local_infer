# 家庭 AI 集群:从买硬件到跑任务

> 目标体验:**买好硬件 → 每台跑一遍安装命令 → 各种任务开箱即用**。
> 本页回答四个问题:买什么、配什么、设备怎么联动、能干什么活。

## 1. 硬件清单(按预算三档,可叠加)

| 档 | 要买的 | 在系统里的角色 | 状态 |
|---|---|---|---|
| **入门档** | 一台 24GB 独显机(RTX 4090/4090D/3090,整机约 ¥13k–20k,或按小时租) | 强档专家:32B 模型跑硬活 + 弱档 1.7B 共存跑量 | ✅ 已实测 |
| **标准档** | + 一台常开低功耗机(家里现有的 Mac 即可) | 网关大脑 + 弱档前台 24h 在线;独显机变成按需开机 | 📋 二期 |
| **旗舰档** | + 一台 128GB 大内存主机(NVIDIA DGX Spark / 懒猫 AI Pod ¥29,899 / Perplexity 成品机) | 长文档车道:300B 级 MoE,26 万~100 万 token 上下文,原生看图 | 📋 调研完成 |
| 顺手的 | 家里任何旧电脑 | 装个 Pi 当终端,零成本多一个入口 | 📋 |

一台入门档就是完整可用的系统(现在跑的就是);后两档是叠加增强,不是门槛。

## 2. 用户配置与模型选择

原则:**零配置能跑,配置只为增强**。要用户操心的只有三层:

| 层 | 用户提供什么 | 系统自动做什么 |
|---|---|---|
| L0 必做 | 每台设备跑一遍安装命令 | 探测硬件 → 按下表自动选模型和推理引擎 → 起服务 → 注册进网关 |
| L1 建议 | **云端 API key** 一行(`TOGETHER_API_KEY=...`,或其他 OpenAI 兼容供应商) | 解锁云端兜底:本地模型崩溃/超纲时自动切云端,零中断。不填也能跑,只是降级时用幸存模型顶班 |
| L2 可选 | 换模型档(`INFERENCE_PRESET=`)、家庭策略(云端预算上限、隐私规则「某类任务永不出网」) | 按策略编译路由 |

**硬件 → 自动选择的模型**(强弱双档是调度的基本结构):

| 探测到的硬件 | 弱档(走量,~八成流量) | 强档(破局) | 状态 |
|---|---|---|---|
| 24GB 独显 | Qwen3-1.7B-FP8 | Qwen3-32B-AWQ(未来换 Qwen3.8-27B) | ✅ 实测 |
| 12–16GB 独显 | Qwen3-1.7B-FP8 | Qwen3-8B/14B-AWQ | ⚠️ 外推 |
| 32GB+ 独显 | Qwen3-4B-AWQ(24GB 装不下,这档才行) | Qwen3-32B-AWQ | ⚠️ 外推 |
| Mac(Apple Silicon) | Qwen3 系 4bit MLX | —(强档活交给别的设备) | 📋 二期 |
| 128GB 大内存主机 | 中档稠密模型 | GLM-5.3-Flash / DeepSeek-V4-Flash(300B 级 MoE) | 📋 |
| 云端(填了 key) | — | Claude/GPT/Qwen 大杯(兜底与溢出) | ✅ 路由已通 |

## 3. 设备联动与 I/O

**联动拓扑**——所有设备连向同一个网关端点,各用其长:

```
【Input 入口】                【调度】              【算力】
 pi 终端(任何设备)     ─┐                    ┌─ 常开机: 弱档+judge (24h)
 Web 控制台(:6006,     ─┼→ 网关 Switchyard ──┼─ 独显机: 强档 (开机=归队,
   聊天+文件上传)       │   (常开机上)        │          关机=自动降级)
 OpenAI/Anthropic API ─┘                    ├─ 大内存机: 长文档/看图
 (现有软件直接接入)                           └─ 云端 API: 兜底(需 key)
```

- **联动规则**:设备上线自动注册进池子,下线自动摘除(看门狗 10 秒发现,秒级改路由);独显机的开关机就是成本开关;全部本地车道失效才走云端;
- **Input**:自然语言指令(终端/网页)、上传的文本文件(txt/md/csv/json/代码,≤2MB)、任何 OpenAI 兼容软件的 API 调用;
- **Output**:聊天回答(标注哪台设备哪个模型干的、延迟、tok/s)、**真实执行结果**(agent 创建的文件、跑出的命令输出)、API 响应、控制台上的路由过程与成本账本。

## 4. 任务指令与规划

用户不需要懂强弱档——默认 `auto`,系统自己分。分配逻辑一句话:**每个任务先让弱档干,
judge 盯着干活轨迹,确认卡在"弱档能力之外"才升强档,升了就不再降(单程票)**;
显式指定 small/large/cloud 永远直通。(judge 的完整官方判据见 docs/home-cluster.md)

**四类任务与具体例子**:

| 类型 | 谁干 | 例子(可直接照抄) |
|---|---|---|
| **秒回类**(高频便宜) | 弱档 | 「把这段话翻译成英文:…」「这封邮件改得礼貌点:…」「这条评论是好评还是差评:…」「提取这段话里的所有人名」 |
| **专家类**(硬活) | 强档 | 「分析这份合同的违约条款风险」「评审这段代码为什么死锁:```…```」「我们该自建客服还是外包?给利弊分析」 |
| **文档类**(上传文件) | 按长度分档 | 传 Q3 报表→「总结要点,标出异常项」;传 CSV→「哪些行的数据可疑?」;传代码文件→「讲讲这个模块干什么的」 |
| **Agent 类**(多步执行) | 弱档起步,自动升级 | 「写个 python 脚本统计当前目录文件数,保存并运行给我看结果」「把这个仓库里所有 TODO 注释列成清单」「读一下 README,总结这个项目是干嘛的」 |

**规划**(能力路线):

- ✅ 现在:上表全部任务在单机档可用(4090D 真机验证,含故障自动切换演练)
- 📋 二期:多设备自动联动(Mac 接入、设备发现)、长文档车道(128GB 主机 + 300B MoE)、
  看图任务(Qwen3.8-27B / DeepSeek-V4-Flash-Vision)、打通 Google Docs 等外部系统(Pi 扩展)
