# Agent 接口技术设计（Tandem Protocol v1）

> 结论先行：Auto Serving（Tandem）与 Auto Agent（编排器）**进程分开、协议同源、交付合一**。
> 本文档定义两者之间的协议契约 v1。网关侧已实现；编排器是独立的第二个项目，按本契约接入。

## 1. 背景与设计原则

Agent 编排器和推理网关的工程难题完全不同：前者要管沙箱隔离、工具凭据、会话状态、
执行副作用；后者要管显存分片、KV cache、路由准确率。两者捏在一个进程里，任何一边的
升级都拖着另一边过安全审计。因此：

1. **进程分开**——编排器是独立服务（独立仓库），只通过 HTTP 和 Tandem 通信；
2. **协议同源**——接缝就是 OpenAI 兼容 API + 本文档定义的 `x-tandem-*` 扩展头。
   扩展全部放在 HTTP 头里而不是请求体里，请求体保持纯净的 OpenAI 格式原样透传，
   任何标准 SDK 用 `extra_headers` 就能接入，不带扩展头的纯 OpenAI 客户端完全不受影响；
3. **交付合一**——最终 `docker compose --profile agent up` 一条命令拉起两个服务。

分层：

```
┌─────────────────────────────────────────────┐
│  Agent Orchestrator（第二仓库，规划中）        │
│  循环控制 · 工具注册表 · 沙箱执行 · 凭据管理    │
└──────────────┬──────────────────────────────┘
               │ OpenAI API + x-tandem-* 头（本契约）
┌──────────────▼──────────────────────────────┐
│  Tandem Gateway（本仓库，已实现）              │
│  分诊路由 · 缓存 · 升级重答 · 账本             │
└─────────────────────────────────────────────┘
```

安全边界：**工具永远在编排器的沙箱里执行，Tandem 只负责"思考"**，不执行任何东西。
模型返回的 `tool_calls` 对 Tandem 而言只是透传的 JSON。

## 2. 协议契约 v1

### 2.1 请求扩展头（均可选）

| 头 | 值 | 含义 |
|---|---|---|
| `x-tandem-hint` | 步骤类型词（见 2.3） | 调用方对这一步难度的先验提示，影响路由 |
| `x-tandem-session` | 不透明字符串（≤128 字符） | 会话/任务 ID，用于跨请求聚合账本 |

### 2.2 响应扩展头

| 头 | 含义 |
|---|---|
| `x-tandem-protocol` | 契约版本，当前恒为 `1`；编排器据此做兼容协商 |
| `x-tandem-lane` | 实际执行车道 `small` / `large` |
| `x-tandem-reason` | 决策依据（`hint:digest`、`heuristic:...`、`hint-overridden:tools` 等） |
| `x-tandem-cache` | 精确缓存命中时为 `hit` |
| `x-tandem-escalated` | 发生升级重答时给出原因 |
| `x-tandem-session` | 原样回显请求中的会话 ID |

### 2.3 hint 词汇表与路由优先级

Agent 循环里不是每一步都需要大模型。hint 把「这一步是什么类型」告诉网关：

| hint | 车道 | 典型场景 |
|---|---|---|
| `plan` / `reason` / `code` / `large` | large | 任务规划、多步推理、写代码 |
| `digest` / `format` / `classify` / `extract` / `chat` / `small` | small | 工具输出摘要、JSON 格式化、意图分类、字段提取、寒暄 |

**优先级阶梯**（高到低）：

1. 显式指定——`model: "small"|"large"`，永不被推翻；
2. 硬规则——请求带 `tools`，或上下文超过小模型物理容量：即使 hint 说 small 也强制
   large，响应头标注 `hint-overridden:<规则名>`（编排器可据此发现自己的 hint 标错了）;
3. **hint**——覆盖启发式打分；
4. 启发式打分——没有 hint 时的默认路径（`docs/routing.md`）。

未知的 hint 值**静默忽略**、回落到启发式——新版本编排器加新词汇不会砸旧网关，
这是前向兼容的关键规则。

### 2.4 会话账本

带 `x-tandem-session` 的请求按会话聚合：请求数、分车道计数、token 数、缓存命中、
升级次数。查询：

- `GET /admin/sessions/{id}` —— 单会话账本（agent 任务结束后拉一次，得到
  "这个任务花了多少 token、省了多少钱"）；
- `GET /admin/stats` —— 全局账本，含活跃会话数。

会话表按 LRU 上限 1000 条淘汰，账本是运营数据不是计费凭证（v0.1 内存态，重启清零）。

### 2.5 流式与升级的交互（不变式）

- 升级重答只发生在非流式请求上；流式请求的路由在生成前定死。
  编排器对关键步骤（如 plan）应使用非流式以获得升级保护；
- 流式请求如需 token 计数，编排器自行设置 `stream_options.include_usage`。

## 3. 编排器蓝图（第二仓库，未实现）

组件与一轮 agent 循环中的车道分配：

```
用户任务 ──→ 循环控制器
              │ ① plan 步        ──ht:plan───→ large（非流式,受升级保护）
              │ ② 模型返回 tool_calls
              │ ③ 沙箱执行工具（编排器内部，不经过 Tandem）
              │ ④ 工具输出摘要    ──hint:digest─→ small（长输出先压缩,省大模型上下文）
              │ ⑤ 回到 ① 直到完成
              └ ⑥ 最终答案组装   ──hint:reason─→ large
```

关键设计决定（留给第二个项目展开，此处定方向）：

- **沙箱**：工具执行用容器/子进程隔离，文件系统白名单，网络默认关闭按工具开启；
- **工具注册表**：JSON Schema 声明（与 OpenAI tools 格式同构，可直接透传）；
- **凭据**：只存在编排器侧，永不进入 prompt，也就永不到达 Tandem 和 GPU；
- **账本对齐**：编排器为每个任务生成 `x-tandem-session`，任务面板上「这次任务
  成本」直接来自 `GET /admin/sessions/{id}`，两边一本账；
- 步骤 ④ 是协同设计独有的降本点：工具原始输出往往数千 token，先用小模型压缩
  再进大模型上下文，双重节省（小模型干活便宜 + 大模型上下文变短）。

## 4. 未决问题（进入第二项目前需要定）

- 编排器→Tandem 的背压：大车道并发上限（24GB 档实测 ~2）意味着编排器需要任务队列；
- 会话账本持久化（Prometheus / SQLite）随 roadmap v0.2 的可观测性一起做；
- hint 的滥用防护：外部直连用户谎报 `hint:chat` 蹭小模型不构成安全问题
  （答案质量自损 + 升级兜底），暂不设防。
