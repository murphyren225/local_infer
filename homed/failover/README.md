# failover — 云端兜底 + 自愈

「大模型实在靠不住就直接调 API」的实现。两个进程：

**watchdog.sh**：每 10 秒探测两条车道；连续 2 次失败 → 调 router 组件
重生成降级路由 → 重启 switchyard（秒级，用户只感觉换了个模型）→
派 heal.sh 后台修复。修复期间看门狗只观察不插手（`logs/heal.lock`）。

**heal.sh**：分段自愈。实测教训——32B 冷启动装载峰值 ~20.5GiB，
小模型驻留时原地重启必 OOM，所以大模型挂掉时：撤下小模型腾空整卡 →
路由切换（有云端 key 全走云端**零中断**；没 key 明确短暂停机 ~2-5 分钟）→
按验证过的顺序重启 → 恢复正常路由。只有小模型挂时直接原地拉起（无此问题）。

演练：`./homed/test.sh failover`（破坏性：故意杀 32B，全程 ~3-8 分钟）。
日志：`logs/watchdog.log`（含每次切换和裁决）、`logs/heal.log`。
